# knowledge/ — what we have learned, kept for the next session

Started 2026-10-23 at the user's request: "docs for yourself — invoices and
things that were a blocker but are not now".

`reference/` is the policy (how things must be done); `state/` is data and the
open worklist; **`knowledge/` is the experience**: facts about our suppliers,
our ArmSoft database, which documents mean what, and which blockers have gone
away. Read the file for the area before working there, and **add to it the
moment a blocker is lifted or a fact is learned** — date every entry, newest
first, one fact per bullet, with the document / code / product it is about.
When an entry turns into a rule, move it into the skill or `reference/` doc
and leave a one-line pointer here.

| File | What is in it |
|---|---|
| `resolved-blockers.md` | things that used to stop us and no longer do (or still do), with the date and how |
| `armsoft-documents.md` | the ArmSoft receipts, issue orders and tax invoices we touched, what each one is, and how to read e-invoicing |
| `costs-and-rivals.md` | where a cost comes from, how to confirm it against hafo's wholesale price, per-kg traps, cases checked |
| `goods-setups.md` | how each kind of good is set up in ArmSoft (bag + kg, pack + single, boxes, litter) and why |
