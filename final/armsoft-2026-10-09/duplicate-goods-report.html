What happened

On 9 October we imported the Royal Canin range into ArmSoft as codes 1342–1408. Each of these has the barcode printed on the pack, a scale code for selling loose by the kilo, and the same price as the website.

Around the same time, someone entered the same Royal Canin bags and boxes by hand as codes 1443–1472. Their names are copied from Royal Canin's supplier price list (for example «SHN Maxi adult», «SENSIT CTRL CK 12X85G INT»). These codes have no barcode and no price.

So each of these 30 products now has two codes. We have not deleted them, because they may have stock or documents on them that we can't see in the export.

Why this is a stock problem

Scanning a bag at the till always picks the code with the barcode (1342–1408). If the delivery was received on the hand-made code (1443–1472), then:

  • the hand-made code shows bags in stock that have already been sold;
  • the barcode code goes negative, or shows less than is on the shelf;
  • stock counts and reorders for these products will be wrong, and a product can look sold out while it is on the shelf (or the other way round).

The same happens if one person receives on one code and another sells on the other. The fix is that every product has one code, and that stock is received on the same code the till sells.

Questions for the person who added codes 1440–1473

  1. Did you create these codes, and from what?The Royal Canin price list, a supplier invoice, or something else?
  2. Was any stock received on them?Which codes, how many bags or boxes, and on which purchase document?
  3. Was anything sold on them?For example, a sale typed in by code instead of scanned.
  4. Do we sell whole Royal Canin boxes, or only open them and sell pouches?This decides whether the box codes stay at all.
  5. What are 1440, 1441 and 1442?Brand and pack, so they can be added to the website with a barcode and price.

What we suggest once those answers are in

  1. Keep the codes with barcodes (1342–1364 and the box codes, if boxes stay). The till, the scale and the website all point to them.
  2. Move any stock from a hand-made code to its pair in the table, with an internal document in ArmSoft, so the history stays.
  3. Then make the hand-made code inactive (or delete it if it has no documents at all).
  4. Going forward: before creating a new good, scan the pack's barcode in ArmSoft. If it finds a good, use that one. Receive deliveries by scanning too, so stock always lands on the code the till sells.
  5. New products are added to the website first and then sent to ArmSoft from one list, so the two never drift apart. Please tell us before creating goods by hand, and we will add them on our side too.
