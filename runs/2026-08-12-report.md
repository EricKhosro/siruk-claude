## Source

Data came from the brand's official site, `royalcanin.com`, read through the
site's own product JSON (`/_next/data/…`, the payload its product pages render
from) plus the public catalogue index at
`rc-api.royalcanin.com/internal/product-digital-shelf/products/facets`.
Read-only; no cart, no account. Notes:

- `curl` gets **403** from `www.royalcanin.com` (WAF). The page JSON must be
  fetched from inside the browser (chrome-devtools `evaluate_script` + `fetch`).
  The catalogue index host (`rc-api.royalcanin.com`) *does* answer curl, with the
  site's public `ocp-apim-subscription-key`.
- **UK site (`/uk`, en-gb)** covered 27 of 33 rows.
- **3 rows are not sold in the UK** and were sourced from Royal Canin's
  English-language UAE site (`/ae`, en-ae): Mini Indoor Adult, Mini Indoor Puppy,
  Savour Exigent. Same manufacturer copy, English, so not treated as "fallback".
- **3 rows are veterinary diets** (`vet` product pillar, not retail): Urinary S/O,
  Satiety Weight Management, Renal with Chicken.
- Prices/stock always from the CSV; every price on the brand site ignored.

## Pricing model (applied 2026-08-12)

Two kinds of product, per your rule — see `reference/data-tables.md` table 4:

| | Variants | Shape |
|---|---|---|
| **Sold by weight** (dry kibble) | **18** | `pricing_type: "per_kg"` + `price_per_kg` (= CSV price ÷ pack weight) + `weight`; no `product-weight` attribute |
| **Sold by count** (wet pouches/cans/multipacks, milk powder) | **15** | `pricing_type: "fixed"` + `price`, as before |

Every rate reproduces the CSV pack price (worst drift 0.05 AMD — the API keeps
only 2 decimals on the rate). Examples: Mini Adult 8 kg = 3312.50/kg → 26,500;
Satiety 3.5 kg = 4714.29/kg → 16,500.02; Sterilised 37 15 kg = 4000/kg → 60,000.

Two things to know about how the API behaves here:

- **`price` is ignored on a `per_kg` variant** — it is stored as 0 and the price
  comes from rate × pack weight. So the rate *is* the price.
- **`pricing_type` accepts only `fixed` or `per_kg`.** ("weight", "by_weight",
  "priced_by_weight" all 422.)

**Judgment call to confirm:** I treated **Babycat Milk 300 g** (powder tin) as
sold by count, not by weight — you buy the tin, and AMD/kg isn't how a milk
replacer is shopped. Same for the 195 g Mother & Babycat can. Tell me if either
should be weight-priced.

**One conflict with your second instruction**, worth a dev-team fix: the API
requires each variant of a product to have a unique attribute combination. On
**Sterilised 37** (15 kg + 2 kg) the two variants differ *only* by pack size, so
dropping `product-weight` made their attributes identical and the API refused the
second variant. That product keeps `product-weight`; every other weight-priced
variant has it removed as instructed. If the backend counted `weight` (or the
generated weight) toward variant uniqueness, the exception would disappear.

## Reproducing / re-running

- `runs/2026-08-12-royal-canin/plan.tsv` — the plan: one row per CSV row with
  product grouping, SKU, prices, stock, and the exact attribute ids.
- `runs/2026-08-12-royal-canin/import.sh` — the driver (bash + jq). Resumable and
  idempotent: it skips rows whose SKU is already on the product, so re-running is
  safe. `import.sh <product_key> …` re-runs a subset.
- `.siruk-cache/rc-extract.json` — the raw extraction for all 32 source pages
  (description, benefits, composition, feeding guide, packs with article codes,
  image URLs). Re-extraction needs the browser (WAF blocks curl).
- `.siruk-cache/rc-created.json` — product_key → admin id.

  the media endpoint returns **500** on Royal Canin's 5000×5000 packshots — and
